# Review convergence loop, finding-verifier, and merge-with-followup at cap

**Status:** accepted — refines ADR 0022 (flight owns the review wave), ADR 0027 (retro counters), ADR 0034 (write-ahead resume state); amends the finding-handling rules only. Does not touch ADR 0017's queue writer table.

Expert-review findings had three silent exits: `Minor` was noted and never fixed, an un-evidenced `Critical` was rejected without a bounce, and a `NeedsVerification` doubt was recorded and dropped. All three wrote to `review-result.json` and died there — no backlog, no retro lane, no follow-up. A fourth exit, bounce-cap exhaustion, marked the slice `blocked` and discarded green committed work. This ADR closes all four: every finding is either fixed, refuted with evidence, or carried forward as a followup — and a slice never blocks on review quality again.

## Context

- **Write-only findings.** `Minor → note, don't block` (flight Step 3) meant Minors accumulated across a Task with no consumer. `impl/triage.md` ingests only human-QA findings, so nothing routed them.
- **Unproven claims were free to raise and free to ignore.** The evidence gate (added to stop false Criticals from missing-coverage illusions) worked as a filter but had no second half: `Unsubstantiated` and `NeedsVerification` were terminal states. A reviewer's real find, stated without a cite, was indistinguishable from a hallucination — both were discarded.
- **Runtime drift.** The Codex runtime (`.agents/skills/e2e-flight/SKILL.md`) listed `NeedsVerification` / `Unsubstantiated` in the *severity* enum and sketched a "targeted read-tool reviewer" that the Claude runtime never had. The two runtimes disagreed on both the vocabulary and the flow.
- **Cap exhaustion threw away green work.** `Bounce cap = 3 → mark slice blocked, tear down worktree` discarded a slice whose tests passed, because a reviewer's quality gap survived three rounds. The Task then carried a `blocked` slice into human-QA with no repair path queued.
- **Mechanical-tier skip was load-bearing on trust.** `skip re-review: mechanical, diff confirms no logic change` asserted a diff property without a second reader confirming it.

## Decision

1. **Review convergence loop replaces the three-tier bounce cap.** Per slice: review wave → verify wave → `open[]` → merge if empty, else bounce → re-review → loop. Merge gate is `open[] == []` for **all** severities, `Minor` included (sole exception: cap exhaustion, decision 5). `bounceRounds` is counted **per slice, absolute** — findings newly surfaced by a re-review do not reset it. **Cap = 4** (was 3).
2. **Tier selects re-review SCOPE, never whether.** `mechanical` / `limited` → re-dispatch every reviewer that raised an open finding this round (amended during implementation: with a fix pass repairing ALL open findings at once, re-dispatching only the single triggering reviewer let a second reviewer's finding be flipped to `fixed` unread — the loss class this ADR exists to close). `logic change` → full re-review wave. The `skip re-review: mechanical` exemption is **retired** — no fix merges unread. `Minor` is an ordinary finding: it piggybacks any bounce, and a Minor-only round is a legal round that consumes one.
3. **`finding-verifier` — one new read-only agent for both unproven states.** Canonical spec `skills/e2e-engineering/agents/finding-verifier.md`. Two triggers, one contract: a `NeedsVerification` doubt (prove or refute inside the disputed scope) and an un-cited `Critical`/`Important` (find the cite or refute the claim). Budget ≤8 tool calls. Returns `{ findingId, resolution: confirmed|refuted|inconclusive, severity?, evidence, reason }`. `confirmed` + cite → enters `open[]` and bounces. `refuted` → `dropped-refuted`, logged. `inconclusive` → **treated as refuted** (adversarial default; a budget-exhausted verifier must not manufacture bounces). Independent of the reviewer that raised the finding — no self-confirmation.
4. **Verify-once, then suppress.** A verify wave runs after **every** review and re-review fan-in, but each individual finding is verified **at most once per slice**; a `dropped-refuted` finding may not be re-raised by a later re-review. The orchestrator suppresses by finding key (`severity` + `location` + message hash), tracked in `resume.json`. Without this the loop cannot converge — the same refuted claim returns every round. The verify wave does **not** consume a bounce round (it is not a fix).
5. **Cap exhaustion merges and hands forward; review-driven `blocked` retires.** At round-5 entry the slice **merges** (its tests are green; the residue is a quality/coverage gap, not a red test). `prd.json` story → `status: done`, `notes` records the open count and severities. Survivors carry `state: "open-at-cap"` in `review-result.json` and are appended to a new `tasks/<id>/followups.json`, each with a per-entry `suggestedPriority` (`Critical` → 1, `Important`/`Minor` → 3, so one file may hold a mix — amended during implementation: a per-file uniform value would retroactively promote an earlier slice's nit to P1, destroying information). `qa-signoff.md` always gains `## Followups`; it gains `## Release Blockers` **iff** an open `Critical` exists.
6. **Flight does not create queue entries — the followup rides the artifact lane.** ADR 0017's writer table is untouched: flight still only flips `queue.json` status. `impl/triage.md` gains intake source #4 (flight followups) → each becomes a queue Task `status:needs-spec`, `selected:false`, `parentTask=<task id>`, priority from `suggestedPriority`. The interactive front door owns creation, as it already does for human-QA findings.
7. **Findings carry a STATE; `NeedsVerification`/`Unsubstantiated` leave the severity enum.** `severity` stays exactly `Critical | Important | Minor`. New sibling fields: `evidence`, `signal` (`NeedsVerification | null` — added during implementation: the hygiene gate instructs reviewers to raise `NeedsVerification`, but this decision deliberately leaves the severity enum with no slot for it, so it needs its own field; `severity` continues to carry the severity the reviewer would assign), `state` (`open | fixed | dropped-refuted | open-at-cap`), and a `verification` sub-object. `Unsubstantiated` retires — a claim is now spent on a verifier before it can be dropped. Both runtimes converge on this vocabulary, ending the drift.
8. **Bounce and verify state is write-ahead (ADR 0034 conformance).** `resume.json` gains `bounce` and `suppressed` keyed PER SLICE plus `verifyWave[]`, all written before every bounce and verify dispatch (amended during implementation: a singleton `bounce` cannot represent the parallel ready set — one slice entering its review wave would reset another's `rounds` or clear another's suppression, reintroducing both the unbounded churn and the non-convergence this decision and decision 4 exist to prevent). A durable round counter is mandatory: without it a mid-loop death restarts the count and the slice churns unbounded — the same failure class ADR 0034 fixed for `gate5Strikes`.
9. **Anti-inflation guards.** "Fix every finding" pays reviewers to pad, so: every finding at any severity must carry a cite AND imply an ACTION. The existing downgrade rule extends — `Important` + "no change required" → `Minor`; `Minor` + "no change required" → **dropped**. Un-cited `Critical`/`Important` → verifier. Un-cited `Minor` → **dropped, no verifier spend** (a Minor worth fixing is worth citing; verifying nits inverts the cost curve). Reviewer budget stays ≤15 calls.
10. **GATE 3 is unchanged.** Three failed fixes on *red tests* still marks the slice `blocked`. Only the review-quality block retires. A red test is not a quality gap and must never merge behind a followup.

## Considered Options

- **Minor as a full bounce peer** (own tier, own re-review) — rejected: a logic-touching Minor would trigger full re-review waves that surface more Minors, exhausting the round budget on cosmetics.
- **Minors deferred to an auto-generated post-DAG cleanup slice** — rejected: keeps per-slice waves fast, but merges each slice with known open findings, which is exactly the write-only exit this ADR closes.
- **Two specialized verifiers** (`coverage-verifier` + `evidence-hunter`) — rejected as YAGNI: both jobs are "produce a cite or withdraw", differing only in the input state label.
- **Re-dispatch the originating reviewer to substantiate its own claim** — rejected: the reviewer confirms its own hunch; independence is the whole value of the verify wave.
- **Flight appends the followup Task to `queue.json` in its existing Step-5.1 master commit** — rejected: cheaper and needs no human step, but it grants flight creation rights over the queue and breaks ADR 0017's writer disjointness. Cost accepted: a followup only reaches the queue once a human runs QA sign-off.
- **Flat followup priority regardless of severity** — rejected: an unresolved `Critical` would look identical to an unresolved nit at sign-off.
- **Keeping `blocked` for an open `Critical` at cap** — rejected per the "don't block, keep draining" objective; the P1 followup plus the `## Release Blockers` section carries the same signal without discarding green work.

## Consequences

- Worst-case per-slice review cost rises: 4 bounce rounds (was 3), each now re-reviewed (mechanical no longer skips), plus one verify wave. The verify wave is cheap (≤8 calls per unproven finding) and the mechanical/limited re-review is single-reviewer, so the added cost is bounded, not multiplicative.
- A slice can merge with a known open `Critical`. This is deliberate and made loud in two places (`## Release Blockers` in `qa-signoff.md`, P1 followup). Auditability rests on `followups.json` — if the human skips sign-off, the followup never reaches the queue, and the artifact on the task branch is the only record.
- Reviewers must now cite `Minor` findings to have them actioned, which changes reviewer output shape. All four review-wave reviewer specs (`backend-architect`, `dba`, `frontend-reviewer`, `test-reviewer`) need the severity semantics updated; `product-designer` (pre-build advisory) and `architecture-scout` (deslop) are untouched.
- `flow-retro.md` loses the `rejected un-evidenced Criticals` counter (the state no longer exists) and gains bounce rounds per slice, verifier spend (confirmed/refuted/inconclusive), open-at-cap → followups (P1/P3), and dropped un-cited Minors.
- CONTEXT.md gains glossary entries for the convergence loop, `finding-verifier`, finding state, and `followups.json`; the `Expert-review wave` entry needs its un-evidenced-Critical sentence rewritten.
